# Jellyfin Plugin: Enhanced Next Up

## Overview

This plugin modifies Jellyfin's `Next Up` behavior.

By default, Jellyfin determines the next episode for a series based on the highest watched episode in the series.

Example:

Watched:
- S01E01
- S01E02
- S01E10

Jellyfin Next Up:
- S01E11

For some viewing patterns this can produce unintuitive results.

This plugin instead determines Next Up using the most recently watched episode.

Example:

Watched:
- S01E01
- S01E02
- S01E10

Most recently watched:
- S01E02

Plugin Next Up:
- S01E03

The goal is to make Next Up reflect what the user is actively watching rather than the furthest point reached in a series.

---

## Design Goals

- No modifications to Jellyfin server source code.
- Implemented entirely as a standard Jellyfin plugin.
- Compatible with all Jellyfin clients.
- Operates server-side.
- Leverages Jellyfin's existing `/Shows/NextUp` endpoint.
- Allows per-series configuration.
- Preserves existing Jellyfin behavior where desired.

---

## Technical Approach

The plugin should:

1. Allow Jellyfin to generate the normal `/Shows/NextUp` result.
2. Intercept the response using an MVC action/result filter.
3. Examine each Next Up item.
4. Determine whether the series is managed by this plugin.
5. Replace Jellyfin's selected episode with an alternative episode computed using this plugin's algorithm.
6. Return the modified response.

The implementation should follow a similar architecture to the community plugin:

- jellyfin-plugin-nextup-cleanup

which demonstrates modification of `/Shows/NextUp` responses using action filters.

---

## Episode Selection Algorithm

For a series using Enhanced Next Up:

### Step 1

Find the most recently watched episode for the current user.

### Step 2

Find the next sequential episode in the series.

Examples:

- S01E01 -> S01E02
- S01E10 -> S01E11
- S01E24 -> S02E01

### Step 3

Skip already watched episodes until the first unwatched episode is found.

Example:

Watched:
- S01E01
- S01E02
- S01E03

Most recently watched:
- S01E01

Candidate:
- S01E02

Already watched.

Next candidate:
- S01E03

Already watched.

Result:
- S01E04

Return the first unwatched episode.

---

## Completed Series Behavior

If all standard episodes in a series are watched:

- No Next Up entry should be generated by the plugin.
- Jellyfin's default behavior may continue to apply if appropriate.
- The plugin should not generate artificial Next Up entries.

Example:

Series completed:
- All episodes watched

Result:
- No plugin-generated Next Up item

---

## Per-Series Configuration

Each series should support enabling or disabling Enhanced Next Up.

Default:

- Enabled

Reason:

Most users installing this plugin likely want the new behavior everywhere.

Example:

Series A:
- Enhanced Next Up enabled

Series B:
- Enhanced Next Up disabled

For Series B:
- Use Jellyfin's native Next Up behavior.

---

## Series Metadata Storage

Investigate one of the following approaches:

### Option A

Store plugin settings using Jellyfin plugin configuration with mappings:

```json
{
  "seriesId": true
}
```

### Option B

Store plugin data using custom item metadata.

### Option C

Use tags or collection membership.

Preferred solution:

Whatever best survives library rescans and Jellyfin upgrades.

---

## Specials Handling

Default:

- Specials should NOT influence Next Up calculation.

Watching:

- Special 1
- Special 2

should not change:

- S01E05 -> S01E06

behavior.

Optional plugin setting:

```text
Include specials in Next Up calculations
```

Default value:

```text
false
```

---

## Multi-Episode Files

Must be handled correctly.

Examples:

File contains:
- S01E01-E02

If watched:

Result should continue to:

- S01E03

not

- S01E02

The plugin should use Jellyfin's episode numbering information rather than assuming one episode per file.

---

## Rewatch Scenarios

Example:

Originally watched:
- All episodes

Months later:

User watches:
- S01E01

Most recently watched:
- S01E01

Plugin result:
- S01E02

This is expected behavior.

The plugin should prioritize recent viewing activity over historical completion state.

---

## Season Jump Scenarios

Example:

Watched:
- S01E01
- S01E02
- S05E08

Most recently watched:
- S05E08

Result:
- S05E09

This behavior is intentional.

The plugin assumes that the user's most recent activity best represents what they are currently watching.

Per-series disable support allows users to revert to Jellyfin's default behavior when desired.

---

## Performance Requirements

The plugin should:

- Avoid excessive database queries.
- Cache lookups where appropriate.
- Minimize additional latency on `/Shows/NextUp`.
- Remain responsive for libraries containing thousands of episodes.

---

## Compatibility Targets

Initial target:

- Jellyfin 10.11.x

Future versions:

- Target latest supported Jellyfin releases where API compatibility permits.

## Non-Goals

The plugin will NOT:

- Replace Jellyfin's recommendation engine.
- Modify watch status.
- Modify playback history.
- Modify resume points.
- Require client-side plugins.
- Require Jellyfin server patches.
